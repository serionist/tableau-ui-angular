## Refuted

A closed `<dialog>` with an inline `display: flex` painting or taking clicks (before `showModal()` all is synchronous;
after `close()` the element goes before the next frame); `showModal()` throwing; a scroll jump when focus lands
off-screen; the reset of the browser's dialog styles; server rendering; the temporary `autofocus` marks; Escape (an
app's `preventDefault()`, the tooltip's listener, date and time inputs, a `closeOnEscape: false` modal, no library
component stopping it); `cancel` and `close` routing; the backdrop (hosted overlays, the modal's border, a drag from a
field, touch, other buttons); sibling modals and their layers; `$overlayHost` set just before `showModal()`; a menu
with no Tab stops; focus back for the wizard, a confirmation from a modal and a removed opener; the confirmation's
removed hook (not exported, and named); leaks; `afterNextRender` focus in content; data set after `openModal()`
returns; Escape no longer clearing a search field in a modal that ignores Escape (by design); the backdrop's custom
property; vacuous tests.

Round 2: the menu's hand-off order, nested menus, a menu inside a modal, a wizard from a modal's menu, a menu that stays
open, an async handler; a held modal closed before it shows, an error in the outer render, two levels deep, Escape
while one is held, the outer modal closing during its render, the snack stack following the host; the regions the
Tab trap walks; the confirmation's description present at focus; the early icon render on the server and during
change detection; the docs and PR text; the delta's tests.
